2. **Security surface has at least 6 open holes (I-244 through I-249).** Every one is easy or medium effort. IDOR on `/api/vin/leads/summary`, AI system prompt writable via URL by org_admin, role dropdown exposes all 8 roles, slug PATCH breaks embeds silently, bad timezone silently blocks outbound, self-deactivation without reactivation path. **All must be closed pre-launch.** None are in a sprint today.

3. **Behavioral test gaps are wide** (I-203 through I-213). Streaming UI render, session timeout UX, campaign execution end-to-end, takeover sequence, API error recovery — all untested. Tests "falsely pass" because API returns 200 but UI behavior isn't checked. Phase 2 visual gates will catch many of these; the rest belong in Phase 4.

4. **Billing module is functionally dead.** I-105, I-171, I-278 — FlexPrice is scrubbed, Lago is the replacement, integration is post-launch. All 26 billing UI states exist as pages but back-end returns `{configured: false}`. Every billing tile degrades to "Billing Not Configured". **Do not block launch on billing.**

5. **Trigger system has two overlapping code paths.** `server/services/triggerService.ts` handles after-hours + 24h check-in as first-class. `server/services/scheduler.ts:563+` (`checkTriggerConditions`) handles `new_lead_followup` + `stale_lead` triggers configured per-agent. Both write outbound SMS via `processOutboundSend`. An org with both enabled could dedup-fail. Not broken but fragile. **Phase 4 — consolidate.**

6. **Production environment is not fully separated from dev.** I-200/I-215-224 (IN SPRINT I-001/I-002/I-003) — Coolify container runs, live deployed, but staging DB, production .env, monitoring are all still being finalized. **Does not block v2.2 inventory but blocks safe launch.**

7. **Email delivery stack is fragile.** I-239 (Resend rate limit exhausted with 483 failures), I-235 CLOSED (user-creation bypassed kill switch), I-236 (OPEN — webhook secrets optional). Every outbound email path needs a) CommGate check, b) kill-switch check, c) rate-limit/retry, d) idempotency. Only (a) and (d) are consistently applied.

8. **No staff-to-staff messaging exists.** TeamBox is the unified inbox but treats every conversation as customer↔org. There is no direct-message schema for users. If "staff messaging / TeamBox" was the same feature to the operator, it is WORKING. If staff-to-staff DM was expected, it is MISSING.

9. **No calendar integration.** Appointments are DB-only rows. No email-to-admin, no ICS attachment, no Google Calendar push. If the operator expected an admin email with calendar invite on appointment intent, that is a net-new Phase 2 scope item (not discovered in code).

10. **Insights page has never been screenshot-verified** (I-156, I-163). ~37 states in state enumeration. Before committing to Phase 2 "insights verified", a dedicated visual audit is required.

11. **Test accounts co-mingled with real data in single Supabase DB** (I-218). Any "live test" touches production data. All IRREVERSIBLE ops in the environment are therefore production-impact.

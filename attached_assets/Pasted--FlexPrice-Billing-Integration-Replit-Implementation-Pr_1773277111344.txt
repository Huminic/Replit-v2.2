# FlexPrice Billing Integration — Replit Implementation Prompt

## Context

Nexxus Connect is an AI engagement platform for car dealerships. We use **FlexPrice** (https://flexprice.io) as our external billing/metering engine. The FlexPrice account is already fully configured with plans, meters, features, prices, entitlements, and live customer data. Your job is to integrate FlexPrice into the Nexxus codebase so the app can:

1. Check what a customer is entitled to (feature gates)
2. Track usage in real-time (emit events to FlexPrice meters)
3. Show billing/usage data in the UI
4. Enforce limits (block actions when entitlements are exhausted)

---

## FlexPrice API Reference

**Base URL:** `https://api.cloud.flexprice.io/v1`
**Auth Header:** `x-api-key: <key>` (store in `.env` as `FLEXPRICE_API_KEY`)

### Key Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/customers?external_id={orgId}` | Look up customer by Nexxus org ID |
| GET | `/subscriptions?customer_id={custId}` | Get active subscription |
| GET | `/entitlements?plan_id={planId}` | Get plan entitlements (features + limits) |
| POST | `/entitlements/check` | Check if customer can use a feature: `{ customer_id, feature_key }` |
| POST | `/events/usage/meter` | Get usage for a meter: `{ meter_id, customer_id, start_date, end_date }` |
| POST | `/events` | Ingest a usage event (async, returns 202) |
| GET | `/invoices?customer_id={custId}` | Invoice history |
| GET | `/wallets?customer_id={custId}` | Wallet list |
| POST | `/wallets/{id}/balance` | Get real-time wallet balance |
| POST | `/wallets/{id}/topup` | Add credits to wallet |
| GET | `/plans` | List all plans |
| GET | `/plans/{id}` | Plan details |

### Response Format
- List endpoints: `{ items: [...], pagination: { total, limit, offset } }`
- Single record: object directly
- Event ingestion: 202 (async)
- Amounts are in dollar strings (e.g., `"2400"` = $2,400)

## Implementation Plan

### Phase 1: Billing Service (server/services/billingService.ts)

Create a service that wraps all FlexPrice API calls:

```typescript
// server/services/billingService.ts
class BillingService {
  private apiKey: string;
  private baseUrl = 'https://api.cloud.flexprice.io/v1';

  // Core methods:
  async getCustomerByOrgId(orgId: string): Promise<FlexPriceCustomer>
  async getSubscription(customerId: string): Promise<FlexPriceSubscription>
  async checkEntitlement(customerId: string, featureKey: string): Promise<{ allowed: boolean; limit?: number; used?: number }>
  async getUsageSummary(customerId: string, startDate: string, endDate: string): Promise<UsageSummary>
  async emitUsageEvent(orgId: string, eventName: string, properties: Record<string, any>): Promise<void>
  async getWalletBalance(walletId: string): Promise<{ balance: number; currency: string }>
  async topUpWallet(walletId: string, amount: number): Promise<void>
  async getInvoices(customerId: string): Promise<FlexPriceInvoice[]>
  async getPlanDetails(planId: string): Promise<FlexPricePlan>
}
```

**Important implementation notes:**
- Cache entitlements for 5 minutes (they don't change often)
- Cache plan details for 1 hour
- Usage events are fire-and-forget (202 async) — don't await them in the request path
- The `external_id` in FlexPrice maps to the Nexxus `organization.id`

### Phase 3: Entitlement Middleware

Create middleware that checks entitlements before allowing actions:

```typescript
// server/middleware/entitlementCheck.ts
function requireEntitlement(featureKey: string) {
  return async (req, res, next) => {
    const orgId = req.user.organizationId;
    const org = await storage.getOrganization(orgId);
    if (!org.billingCustomerId) return next(); // Skip if not on billing yet

    const check = await billingService.checkEntitlement(org.billingCustomerId, featureKey);
    if (!check.allowed) {
      return res.status(403).json({
        error: 'entitlement_exceeded',
        feature: featureKey,
        limit: check.limit,
        used: check.used,
        upgradeUrl: '/settings/billing/plan'
      });
    }
    next();
  };
}
```

Apply to these routes:
- Creating an agent → `requireEntitlement('agent_slots')`
- Creating a widget → `requireEntitlement('widget_slots')`
- Creating a campaign → `requireEntitlement('campaign_slots')`
- Creating a trigger → `requireEntitlement('trigger_slots')`
- Accessing CRM features → `requireEntitlement('crm_integration')`
- Accessing CRM Guru → `requireEntitlement('crm_guru')`
- Accessing Generative Studio → `requireEntitlement('generative_studio')`
- Accessing Competitive Intel → `requireEntitlement('competitive_intel')`

```tsx
// client/src/components/EntitlementGate.tsx
function EntitlementGate({ feature, children, fallback }: {
  feature: string;
  children: React.ReactNode;
  fallback?: React.ReactNode
}) {
  const { data: entitlements } = useQuery(['entitlements'], fetchEntitlements);
  const allowed = entitlements?.[feature]?.allowed;

  if (!allowed) {
    return fallback || <UpgradeCTA feature={feature} />;
  }
  return <>{children}</>;
}
```

## Important Implementation Notes

1. **Don't block on usage events.** Call `billingService.emitUsageEvent()` without `await` in the request path. Usage tracking should never slow down the user experience.

2. **Cache entitlements aggressively.** Plan entitlements change only when a customer upgrades/downgrades. Use a 5-minute TTL cache (simple Map with timestamps, or React Query staleTime on the frontend).

3. **Graceful degradation.** If FlexPrice API is down, don't block the user. Log the error and allow the action. Billing accuracy matters less than uptime.

4. **The `external_id` link.** FlexPrice customers are linked to Nexxus organizations via `external_id` = Nexxus `organization.id`. When looking up a customer, use `GET /customers?external_id={orgId}`.

5. **Amounts are strings in dollars.** FlexPrice returns `"amount": "2400"` meaning $2,400. Parse accordingly.

6. **Meter event_names must match exactly.** When emitting events, use the exact `event_name` from the meters table: `voice_minute`, `video_minute`, `sms_sent`, `llm_input_tokens`, `llm_output_tokens`, `image_generated`, `video_generated`.

7. **Organizations without billing.** Not all orgs will have FlexPrice set up immediately. Always check `if (org.billingCustomerId)` before making FlexPrice calls. If null, skip billing checks — treat as unlimited (or show "billing not configured" in the UI).

8. **Existing schema fields.** The organizations table already has `subscriptionStatus` (trial/active/cancelled) and `subscriptionTier` (free/pro/enterprise). You can either migrate these to the new billing fields or keep them as a fallback. Preference: keep the old fields for backward compatibility but use the new FlexPrice-backed fields as source of truth when `billingCustomerId` is present.

## 2. Per-Page Data Source Analysis

### 2.1 MainPage (`/`) — AI Chat
- **Data Sources:**
  - **API (real):** `useQuery` for `/api/pipeline/metrics` (PipelineData), `useQuery` for `/api/conversations/:id/messages` (DbMessage[]), `apiRequest('POST', '/api/conversations')` and `apiRequest('POST', '/api/conversations/:id/messages')` for creating conversations/messages
  - **API (real):** Uses `useStreamingChat` hook for streaming AI responses
  - **Lib import:** `agentSuggestions` from `@/lib/chat-types` (hardcoded string array — 5 suggestion prompts)
- **Interactive elements:** Chat input (real — sends to API), suggestion chips (real), file upload dropdown (UI present), metric tile click (opens dialog with hardcoded drill-down data)
- **Status:** Pipeline metric tiles are wired to real API. Chat uses real streaming. Metric drill-down dialogs show locally computed data from the pipeline response.

### 2.2 TeamboxPage (`/teambox`) — Unified Inbox
- **Data Sources:**
  - **API (real):** `useQuery` for `/api/conversations` (Conversation[]), `useQuery` for `/api/conversations/:id/messages` (Message[])
  - **API (real):** `useMutation` for POST reply messages, PATCH take-over, PATCH campaign disconnect, POST create task
- **Interactive elements:** All wired to real API — reply input, take over button, campaign disconnect, task creation
- **Status:** Fully wired to backend. No mock imports. Types defined locally (not imported from mocks).

### 2.3 MyWorkPage (`/my-work`) — Personal Dashboard
- **Data Sources:**
  - **API (real):** `useQuery` for `/api/tasks` (Task[]), `useMutation` for POST/PATCH/DELETE tasks
  - **MOCK imports (Chat tab):** `mockConversations` from `@/mocks/messages`, `mockTeamboxConversations` from `@/mocks/conversations`, `ConversationChannel` type from `@/mocks/conversations`
- **Interactive elements:** Task CRUD is real (API). Chat tab shows mock conversation lists.
- **Status:** Tasks tab = real API. Dashboard tab summary cards = real (task counts). **Chat tab = entirely mock data** (lines 311-315 use `mockTeamboxConversations` and `mockConversations`). Assistant tab functionality unclear (needs further review).

### 2.4 SalesPage (`/sales`) — Sales Dashboard
- **Data Sources:**
  - **API (real):** `useQuery` for `/api/metrics/dashboard` (DashboardMetrics), `useQuery` for `/api/agents` filtered by department, `useQuery` for `/api/leads/summary` (VinSolutions data)
  - **Hardcoded (inline):** `salesMetrics` array defined inline with hardcoded fallback values computed from API response
- **Interactive elements:** Agent cards click → opens AgentConfigPane in right pane (real). Calendar tab uses `AppointmentCalendar` component.
- **Placeholder tabs:** Insights tab and Calendar tab are described as "Placeholder for Wave 2"
- **Status:** Dashboard metrics are from real API. Agents from real API. Lead summary from real API (VinSolutions sync). No mock file imports.

### 2.5 ServicePage (`/service`) — Service Dashboard
- **Data Sources:**
  - **API (real):** `useQuery` for `/api/metrics/dashboard`, `/api/agents?department=service`, `/api/campaigns?department=service`, `/api/campaigns/:id/status`
  - **API (real):** `useMutation` for campaign CRUD, kill switch toggle, CSV upload, campaign execute/stop
- **Interactive elements:** All campaign management wired to real API — create campaign dialog, CSV upload, kill switch toggle, execute/stop, dry run
- **Placeholder tabs:** Insights tab ("Wave 2 service analytics"), Calendar tab ("Wave 2 service appointment scheduling")
- **Status:** Fully wired to backend for campaigns. Comment at top still says "Currently uses getCampaignsByDepartment() from mock data" but code actually uses real API.

### 2.6 MarketingPage (`/marketing`) — Marketing Dashboard
